## M82 laboratory scope

Exactly **two independent fresh Android9/API28 Debug emulators** (`trial: [1, 2]`, `fail-fast: false`). Each uses the **unchanged M81 navigation workflow** except labels / isolated branch / concurrency, unchanged app and zero-permission observer, original PPP, strict bounded same-PID Home→Pix→Home preview cycles (two per emulator), fixed 30-second preflight and two original 2-second settle intervals per cycle, at most four guarded taps per emulator, original geometric and semantic blockers, and one original UIAutomator dump+cat per snapshot with mandatory temp-XML deletion. No retries, new snapshots, extra ADB, broader timeouts, BACK, swipes, screenshots, PDF, real input or payment.

The one M81 pure exception classifier now checks **only the already-raised `xml.etree.ElementTree.ParseError.code` numeric parser error** against six standard `xml.parsers.expat.errors` constants. It outputs only one fixed allowlisted label, on overall BLOCK: `snapshot-ui-xml-no-elements`, `snapshot-ui-xml-unclosed-token`, `snapshot-ui-xml-invalid-token`, `snapshot-ui-xml-mismatched-tag`, `snapshot-ui-xml-trailing-content`, `snapshot-ui-xml-partial-character`, or the existing fallback `snapshot-ui-xml-parse-unconfirmed`. No `position`, raw XML, parsing exception `str`, output bytes, screenshot, UI text, coordinates, PID, financial data, URL or local files are logged. A code diagnoses **the parser's rejection reason only**, not whether ADB, the app, XML serialization, host race or framework caused it.

M82 **PASS only if both native jobs SUCCESS** with two individual cycle PASS markers, one final two-cycle same-PID PASS and post-run external PPP in each, and separate required CI SUCCESS. Any one failing or skipped job is M82 not PASS. An M82 PASS does not establish deterministic reliability or original Release behavior.
