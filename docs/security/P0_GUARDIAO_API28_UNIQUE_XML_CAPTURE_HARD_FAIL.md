# P0 #126 | Falha explícita para erros de dump/read/cleanup XML (laboratório)

Na matriz de arquivo exclusivo [#44226721487](https://github.com/nego001/negresco-finance./actions/runs/44226721487), os trials 1, 2 e 4 terminaram BLOCK com `unique-xml-dump-ack=unconfirmed` antes de qualquer PDF verificado. O trial 3 ainda executava na última observação. Isso revela que a captura com destino exclusivo também pode falhar na confirmação do dump e que essa bateria não homologa o retorno pós-chooser.

O runner antigo `guardiao_pdf_ui_emulator_smoke.py` possui o método `wait_visible`, que captura `RuntimeError`, `ET.ParseError` e `subprocess.TimeoutExpired`, tentando novamente quando um elemento não aparece. Essas tentativas são legítimas para **buscar elementos** em telas comuns, mas inadequadas para uma **falha de integridade da captura XML**. Para o laboratório com destino único, qualquer erro durante dumper, leitura, validação de XML ou remoção do temporário agora converte-se a `CaptureUnconfirmed(Exception)` **fora dos tipos capturados pelo loop de procura**.

O comando ADB, a autorização de ações, número de retornos Home/PDF, mesmo PID, gates de dois snapshots e APK test-only não mudam. Há uma validação de XML sintético em memória antes de passar a resposta ao parser antigo; isso modifica levemente o tempo de execução, por isso o resultado não é diretamente comparável à matriz original. Nenhum conteúdo de XML, nome de arquivo real, stdout/stderr, erro privado ou SHA é publicado. Os três testes dinâmicos novos asseguram: comando ADB falha antes de iniciar retries; conteúdo XML quebrado BLOQUEIA sem novas leituras; e falha de limpeza BLOQUEIA mesmo após leitura válida. O teste de integridade estático confirma que `CaptureUnconfirmed` permanece distinto das exceções engolidas no loop legado.

Esta branch é **isolada e sem workflow Android novo**. Não altera o aplicativo nem representa correção/homologação. O P0 #120 de impressão Release histórica permanece aberto por falta de bytes originais; P0 #126 continua aberto.
